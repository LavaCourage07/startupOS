## Agent 工程结构

本 Agent 由以下工程文件组成，存放于 `${OUTPUT_DIR}/agents/{agent-id}/` 目录下：

| 文件 | 作用 | 修改影响 |
|------|------|----------|
| **Agent.md** | 身份、职责、工作模式。定义 Agent 负责的业务领域和处理能力。 | 修改职责 → 改变 Agent 的工作范围和能力边界；修改工作模式 → 改变 Agent 处理请求的方式；修改原则 → 改变决策标准和判断依据。 |
| **Data.md** | 本体数据模型，定义 Agent 操作的业务对象、字段级约束和数据边界。Agent 通过此文件了解它读写哪些业务数据。 | 增加本体对象 → Agent 获得操作新数据的能力；修改字段约束 → 改变数据验证规则；修改操作类型 → 改变 Agent 对数据的读写权限。 |
| **Process.md** | 处理流程和协作协议，定义任务执行步骤、异常处理规则和与其他 Agent 的协作关系。 | 修改处理步骤 → 改变任务执行流程；修改异常规则 → 改变错误处理方式；修改协作协议 → 改变触发关系和数据传递。 |
| **Memory.md** | 记忆模板，存储用户信息、工作上下文和历史记录。Agent 每次启动时读取此文件恢复上下文。 | 清空 → Agent 会失去对该用户/项目的历史了解；修改用户偏好 → 影响 Agent 的个性化响应；添加新上下文 → Agent 会在后续对话中引用。 |
| **Taste.md** | 沟通风格和个性定义。决定 Agent 用什么语气、什么详细程度、什么方式回复。 | 修改沟通风格 → 改变 Agent 的回复语气和表达方式；修改语言规范 → 影响输出格式和语言选择。 |
| **Tool.md** | 工具权限和技能配置。定义 Agent 被允许使用的基础工具和已安装的 Skill。 | 移除工具 → Agent 将无法执行对应操作；添加工具 → 扩展能力范围；添加/移除 Skill → 改变 Agent 的专业工作能力；修改后需重启 Agent 会话才能生效。 |

**如何修改 Agent**：
- 修改 `Agent.md`、`Data.md`、`Process.md` 中的内容后，Agent 会在下次会话中自动使用新配置
- 修改 `Tool.md` 后需要重启 Agent 会话才能生效
- 建议修改前先读取当前文件内容，确认需要变更的部分
- 每次修改后向用户确认变更内容，确保理解一致
