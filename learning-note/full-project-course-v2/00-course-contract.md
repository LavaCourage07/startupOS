# V2 课程契约：逐文件、可教学、可验收

## 目标

这不是“项目介绍”或“源码索引”。完成 V2 后，学习者应能从一个用户请求出发，定位文件、解释概念、追踪调用链、做小改动、运行对应验证，并说清风险。

## 文件覆盖承诺

1. 以 Git 已跟踪文件为基线，见 [全项目文件地图](02-all-tracked-files-map.md)。
2. 每个 `source` 文件必须拥有直接精读单元；不得以“本目录已讲”替代。
3. 每个测试文件必须配对生产代码，解释测试场景与覆盖缺口。
4. 配置、模板、文档、脚本必须有分类与阅读动作；静态资源至少标明消费者和用途。
5. 每个单元都要留下四类状态：精读、运行、练习、验收。没有全部证据，不能标为“吃透”。

## 单元的教学格式

每个正式单元按下列顺序写，且不允许只列结论：

1. 你现在要解决的具体问题。
2. 本课前置概念，用初学者能理解的例子解释。
3. 图解，以及逐箭头解释图中发生了什么。
4. 打开文件的明确顺序、建议阅读行段、可以暂时跳过的部分。
5. 源码分段精读：输入、状态、分支、输出、失败处理。
6. 调用链和关键类型：谁拥有数据、谁能修改、谁只是适配。
7. 测试：它证明什么，没证明什么，怎样亲手运行。
8. 小实验：先观察，再做最小改动，再验证和复盘。
9. 口头验收：学习者不看稿也能解释的五个问题。

## 课程层次

- 概念课：建立术语与全局模型。
- 文件簇导读：限定 1-4 个强关联文件，讲一条真实链路。
- 逐文件卡：任何 `source` 文件至少有一张直接精读卡。
- 实验课：将多个文件簇放入实际运行、调试、测试或打包过程。
- 复盘课：把改动、测试证据、架构规约和发布风险连成闭环。

## 完成判定

“文件在地图里”只表示计划纳入。只有对应单元的精读、运行、练习、验收均完成，且学习者能独立回答调用链与失败路径，该文件才算真正学会。
