# 单元导读三：关闭以后，怎样继续同一段工作（E21-E30）

## 这一组课解决什么问题

用户关闭应用后，内存会消失。若希望下次还能看到并继续同一段对话，系统必须把足够的信息写进文件，并在启动时把可恢复部分重新交给运行时。E21-E30 只研究这条“保存—读取—恢复”链。

## 先建立直觉

保存不是把正在运行的程序塞进文件，而是制作一张可恢复的快照。快照要保存消息、提示词、模型与项目关联；“正在思考”“某个工具刚启动”等短暂状态不能假装在重启后仍有效。

## 你会依次学到什么

- 会话列表、当前会话与单条会话的关系。
- 新建、更新、重命名、删除、切换的结果与失败返回值。
- JSON 存储、缓存与文件路径各自的责任。
- 历史消息怎样映射回当前模型的运行时格式。
- 模型 API 不兼容、文件缺失、数据演进时该在哪里失败。
- 单元测试能证明的恢复边界与真正重启验收的差异。

## 学完后的能力

你能解释为什么 `null`、`false` 与抛出异常含义不同；也能说清“历史被保存”为什么不自动等于“模型已恢复并继续工作”。

## 与下一单元的关系

会话解决“记住对话”；Skills 解决“让 Agent 在这段对话中获得一套具体工作方法”。
