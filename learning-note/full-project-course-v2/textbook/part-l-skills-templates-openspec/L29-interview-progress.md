# L29：访谈进度管理

> 本课问题：OriginOS 如何追踪和管理项目访谈的进度？

## 小林的场景

小林的项目访谈已经进行了多轮，她想查看当前的进度，了解已经完成了哪些阶段，还有哪些待确认的问题。

她想知道：

- 访谈进度是怎么被记录的？
- 进度文件包含什么？
- 如何查看和更新进度？

## 概念阶梯：进度管理不是“打勾”，而是“状态追踪”

| 通俗理解 | 准确术语 | 边界 |
| --- | --- | --- |
| “进度管理就是打勾” | 进度管理是**状态追踪和问题管理** | 不是简单的打勾，而是动态追踪 |
| “进度文件是一次性的” | 进度文件是**持续更新**的 | 不是一次性的，而是持续维护 |
| “进度管理只有完成/未完成” | 进度管理有**多种状态** | 不是二元的，而是多元的 |

```typescript
// [templates/skills/project-initialization/SKILL.md 第 38—50 行](../../../../templates/skills/project-initialization/SKILL.md#L38)
### 进度文件维护

访谈过程中需要维护一个进度 Markdown 文件，记录：

- 已完成的访谈阶段
- 已识别的业务概念
- 待确认的问题
- 发现的矛盾点
- 下一步计划
```

## 第二段源码：进度状态

```typescript
// 进度状态定义：

| 状态 | 说明 | 示例 |
| --- | --- | --- |
| **Not Started** | 尚未开始 | Phase 2 尚未开始 |
| **In Progress** | 进行中 | Phase 1 进行中 |
| **Completed** | 已完成 | Phase 1 已完成 |
| **Blocked** | 被阻塞 | 等待用户确认 |
| **Skipped** | 已跳过 | 用户跳过某阶段 |
```

## 第三段源码：进度更新

```typescript
// 进度更新流程：

1. **访谈开始时**
   - 创建进度文件
   - 初始化状态

2. **访谈过程中**
   - 更新已完成阶段
   - 记录新识别的概念
   - 标记待确认问题
   - 记录发现的矛盾

3. **访谈结束时**
   - 总结进度
   - 制定下一步计划
   - 归档进度文件
```

## 调用链：进度管理流程

```text
访谈开始
  → 创建进度文件
    → 访谈过程中持续更新
      → 记录已完成阶段
      → 记录新识别概念
      → 标记待确认问题
      → 记录发现矛盾
    → 访谈结束
      → 总结进度
      → 制定下一步计划
      → 归档进度文件
```

## 本课结论

本课建立了访谈进度管理的完整认知：

- **进度管理是状态追踪**：不是简单的打勾
- **进度文件包含**：已完成阶段、已识别概念、待确认问题、发现矛盾、下一步计划
- **多种状态**：Not Started、In Progress、Completed、Blocked、Skipped
- **持续更新**：访谈过程中不断维护
- **访谈结束归档**：总结进度，制定计划
