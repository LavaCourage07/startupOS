# L26：`project-initialization`——项目访谈的两阶段模式

> 本课问题：`project-initialization` 是如何通过两阶段访谈完成项目业务建模的？

## 小林的场景

小林有一个"在线书店"的想法，但她不知道如何将其转化为结构化的业务模型。她打开 `project-initialization`，发现它通过两阶段访谈引导她完成整个过程。

她想知道：

- 两阶段访谈是怎么工作的？
- 每个阶段产出什么？
- 访谈结果怎么被使用？

## 概念阶梯：访谈不是“问卷调查”，而是“对话式探索”

| 通俗理解 | 准确术语 | 边界 |
| --- | --- | --- |
| “访谈就是问问题” | 访谈是**引导式对话**，不是单向提问 | 是双向的，根据回答调整问题 |
| “访谈有标准答案” | 访谈是**探索性的**，没有标准答案 | 不是考试，是共同构建 |
| “访谈结果是一次性的” | 访谈结果是**可迭代的**，可以不断完善 | 不是一次性的，可以多次访谈 |

## 第二段源码：两阶段模式

```typescript
// [templates/skills/project-initialization/SKILL.md 第 11—15 行](../../../../templates/skills/project-initialization/SKILL.md#L11)
1. **Phase 1: 领域发现 (Discovery)** - 引导用户描述具体业务场景，识别行业领域
2. **Phase 2: 业务精炼 (Refinement)** - 结构化追问填补缺口，检测矛盾，完善业务规则
```

**两阶段模式**：

| 阶段 | 名称 | 目标 | 方法 |
| --- | --- | --- | --- |
| 1 | 领域发现 | 从模糊想法到初步模型 | 开放式提问、行业识别 |
| 2 | 业务精炼 | 从初步模型到完整模型 | 结构化追问、矛盾检测 |

## 第三段源码：访谈助手角色

```typescript
// [templates/skills/project-initialization/SKILL.md 第 18—28 行](../../../../templates/skills/project-initialization/SKILL.md#L18)
你是 OriginOS 项目访谈助手（称为"Oracle"），协助用户从模糊的想法出发，逐步构建完整的业务领域模型。

### 核心能力

- 🎯 通过开放式问题引导用户思考
- 🏭 识别行业并提供行业背景知识
- 💬 使用 AskUserQuestion 工具进行互动式对话
- 📊 实时记录和整理业务概念
- ⚖️ 主动发现和提醒潜在矛盾
- ✨ 基于行业最佳实践提供建议

### 对话风格

- 专业、友好、引导性强
- 不预设答案，通过提问激发思考
- 适时提供选项帮助用户理清思路
- 主动总结和反馈，确保理解一致
```

**访谈助手特征**：

| 特征 | 说明 |
| --- | --- |
| **引导性** | 通过提问激发思考，不预设答案 |
| **互动性** | 使用 AskUserQuestion 工具 |
| **记录性** | 实时记录和整理业务概念 |
| **检测性** | 主动发现潜在矛盾 |
| **建议性** | 基于行业最佳实践提供建议 |

## 调用链：项目访谈流程

```text
用户说 "I want to start a project"
  → project-initialization 激活
    → Phase 1: 领域发现
      → 开放式提问（描述业务场景）
        → 识别行业领域
          → 收集初步信息
            → Phase 2: 业务精炼
              → 结构化追问
                → 填补信息缺口
                  → 检测矛盾
                    → 完善业务规则
                      → 生成业务模型
                        → 输出到 data/ontology/
```

## 失败路径：访谈可能出什么问题

| 问题 | 现象 | 原因 |
| --- | --- | --- |
| 用户描述不清 | 无法识别领域 | 开放式问题不够引导 |
| 信息矛盾 | 业务模型不一致 | 没有检测矛盾 |
| 访谈中断 | 进度丢失 | 没有保存进度 |
| 用户疲劳 | 回答质量下降 | 访谈时间过长 |
| 领域识别错误 | 业务模型偏差 | 行业知识不足 |

## 小实验

假设用户说："我想做一个在线书店"


## 本课结论

本课建立了 `project-initialization` 的完整认知：

- **两阶段访谈**：领域发现 + 业务精炼
- **领域发现**：开放式提问，从模糊想法到初步模型
- **业务精炼**：结构化追问，从初步模型到完整模型
- **访谈助手**：引导、识别、记录、检测、建议
- **进度管理**：维护 Markdown 文件，记录进度和产物
