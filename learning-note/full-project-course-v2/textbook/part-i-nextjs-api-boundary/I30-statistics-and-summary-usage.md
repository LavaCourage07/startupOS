# I30：统计和摘要接口的用途与限制

前三节课分别看了统计查询、摘要查询、以及它们的来源和计算方式。这节课总结统计和摘要接口的用途和限制。

## 1. 用途

### 1.1 统计查询的用途

| 场景 | 说明 |
| --- | --- |
| 监控 | 监控项目的活跃度和负载 |
| 调试 | 排查项目级别的问题 |
| 分析 | 分析用户行为和 Agent 性能 |
| 报告 | 生成项目级别的报告 |

### 1.2 摘要查询的用途

| 场景 | 说明 |
| --- | --- |
| 快速了解 | 快速了解单个会话的概况 |
| 列表展示 | 在会话列表中展示关键信息 |
| 状态判断 | 判断会话是否需要关注 |
| 导航 | 作为导航到详细会话的入口 |

## 2. 限制

### 2.1 统计查询的限制

| 限制 | 说明 |
| --- | --- |
| 性能 | 遍历所有会话，大数据量下性能差 |
| 实时性 | 数据可能滞后，不是实时统计 |
| 准确性 | 没有事务保护，数据可能不一致 |
| 扩展性 | 新增统计字段需要修改 Core Service |

### 2.2 摘要查询的限制

| 限制 | 说明 |
| --- | --- |
| 信息有限 | 只返回关键字段，详细信息需要查询完整会话 |
| 计算简单 | 没有复杂的计算逻辑 |
| 实时性 | 数据是实时的，但可能不完整 |

## 3. 最佳实践

### 3.1 统计查询

1. **缓存结果**：使用缓存减少重复计算。
2. **异步计算**：在后台异步计算，前端轮询结果。
3. **分页查询**：如果会话数量多，分页查询。
4. **限制范围**：限制统计的时间范围，如最近 30 天。

### 3.2 摘要查询

1. **预计算**：在会话更新时预计算摘要字段。
2. **索引优化**：为常用查询字段建立索引。
3. **批量查询**：如果需要多个会话的摘要，批量查询。

## 4. 与会话管理的对比

| 维度 | 统计/摘要 | 会话管理 |
| --- | --- | --- |
| 核心性 | 辅助 | 核心 |
| 频率 | 低 | 高 |
| 性能要求 | 可接受延迟 | 实时 |
| 数据一致性 | 可接受不一致 | 强一致 |

## 5. 小实验

不运行项目，回答：

1. 统计查询和摘要查询分别适合什么场景？
2. 统计查询的主要限制是什么？如何优化？
3. 摘要查询的主要限制是什么？如何优化？

参考答案：

1. 统计查询适合监控、调试、分析。摘要查询适合快速了解、列表展示。
2. 性能。缓存、异步计算、分页、限制范围。
3. 信息有限。预计算、索引优化、批量查询。

## 6. 章节收束

本节课总结了统计和摘要接口的用途和限制。它们是调试和监控的窗口，不是业务逻辑的核心。
