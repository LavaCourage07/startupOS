# M22 资源管理策略如何阅读——从版本控制到平台适配

小林想知道 OriginOS 的资源文件是如何管理的。她看到 `resources/` 目录下的文件都是版本控制的，但不知道资源文件的更新流程和平台适配策略。

本课解决一个理解问题：当你面对 OriginOS 的资源文件时，怎样理解资源管理策略、版本控制、以及平台适配。

## 场景：从"静态文件"到"动态管理"

### 1.1 资源管理的挑战

OriginOS 的资源管理面临以下挑战：

| 挑战 | 描述 | 影响 |
| --- | --- | --- |
| 多平台适配 | 不同平台需要不同格式的资源 | 增加维护成本 |
| 版本控制 | 资源文件需要与代码版本同步 | 版本不一致可能导致构建失败 |
| 更新流程 | 资源更新需要经过测试和验证 | 更新不及时可能影响用户体验 |
| 大小控制 | 资源文件会增加构建产物的大小 | 影响下载和安装速度 |

### 1.2 资源管理策略概览

OriginOS 的资源管理策略：

| 策略 | 描述 | 实现方式 |
| --- | --- | --- |
| 版本控制 | 资源文件与代码一起版本控制 | Git 管理 |
| 平台适配 | 为不同平台准备合适的资源格式 | 条件编译/打包 |
| 懒加载 | 非关键资源延迟加载 | 运行时动态加载 |
| 缓存 | 资源文件缓存以提高性能 | 浏览器/Electron 缓存 |

## 2. 版本控制

### 2.1 资源文件的版本控制

OriginOS 的资源文件与代码一起版本控制：

```
resources/
├── .gitignore          # 忽略不需要版本控制的文件
├── icons/
│   ├── icon.icns       # 版本控制
│   ├── icon.png        # 版本控制
│   └── ...
└── entitlements.mac.plist  # 版本控制
```

**关键理解**：资源文件与代码一起版本控制，确保每次构建都使用正确的资源版本。

### 2.2 资源文件的更新流程

| 步骤 | 操作 | 责任人 |
| --- | --- | --- |
| 1 | 修改资源文件 | 设计师/开发者 |
| 2 | 提交到 Git | 开发者 |
| 3 | CI 构建验证 | CI 系统 |
| 4 | 测试验证 | QA |
| 5 | 合并到主分支 | 维护者 |

## 3. 平台适配

### 3.1 平台适配策略

| 平台 | 图标格式 | 权限配置 | 特殊处理 |
| --- | --- | --- | --- |
| macOS | `.icns` | `.plist` | Notarization |
| Windows | `.png`、`.ico` | — | 代码签名 |
| Linux | `.png` | — | AppImage |

### 3.2 平台适配的实现

`electron-builder.yml` 中的平台适配：

```yaml
mac:
  icon: ../../resources/icons/icon.icns
  entitlements: ../../resources/entitlements.mac.plist

win:
  icon: ../../resources/icons/icon.png

linux:
  icon: ../../resources/icons/icon.png
```

**关键理解**：平台适配通过构建配置实现。不同平台使用不同的资源文件，但构建流程是相同的。

## 6. 口头验收

学完本课后，不看正文也应能回答下面五个问题：

1. 资源管理面临哪些挑战？OriginOS 如何应对？
2. 资源文件的版本控制方式是什么？
3. 资源文件的更新流程包括哪些步骤？
4. 平台适配是如何实现的？
5. 当你需要更新资源文件时，应该按什么步骤操作？

合格回答不要求背诵每个步骤的具体命令，但必须能说清资源管理策略、版本控制、以及平台适配。能说清"如何管理资源"比只说清"资源是什么"更重要。
