# M27 测试执行和报告如何阅读——从 `pnpm test` 到测试报告

小林想知道 OriginOS 的测试是如何执行的、测试报告在哪里、以及如何解读测试报告。

本课解决一个理解问题：当你面对 OriginOS 的测试执行和报告时，怎样理解测试的执行方式、报告的结构、以及如何判断测试结果。

## 场景：从"执行测试"到"解读报告"

### 1.1 测试执行的方式

OriginOS 的测试执行方式：

| 命令 | 作用 | 范围 |
| --- | --- | --- |
| `pnpm test` | 执行所有测试 | 全部 |
| `pnpm test:unit` | 执行单元测试 | 单元测试 |
| `pnpm test:integration` | 执行集成测试 | 集成测试 |
| `pnpm test:e2e` | 执行 E2E 测试 | E2E 测试 |
| `pnpm test:watch` | 监视模式执行测试 | 全部 |

### 1.2 测试执行的过程

测试执行的过程：

```
1. 启动测试环境
2. 加载测试文件
3. 执行测试用例
4. 收集测试结果
5. 生成测试报告
```

## 2. 测试报告的结构

### 2.1 测试报告的内容

测试报告通常包含以下内容：

| 内容 | 说明 | 示例 |
| --- | --- | --- |
| 测试套件数量 | 有多少个 `describe` | 5 suites |
| 测试用例数量 | 有多少个 `it` | 20 tests |
| 通过数量 | 通过的测试 | 18 passed |
| 失败数量 | 失败的测试 | 2 failed |
| 跳过数量 | 跳过的测试 | 0 skipped |
| 执行时间 | 总执行时间 | 10.5s |
| 覆盖率 | 代码覆盖率 | 85% |

### 2.2 测试报告的解读

| 结果 | 含义 | 处理 |
| --- | --- | --- |
| ✅ PASS | 所有测试通过 | 可以继续提交代码 |
| ❌ FAIL | 有测试失败 | 需要修复失败的测试 |
| ⏭️ SKIP | 有测试被跳过 | 检查跳过的原因 |
| ⏱️ TIMEOUT | 测试超时 | 检查测试代码或环境 |

## 3. 测试失败的排查

### 3.1 测试失败的常见原因

| 原因 | 说明 | 解决方法 |
| --- | --- | --- |
| 代码变更 | 代码变更导致测试失败 | 更新测试或修复代码 |
| 环境问题 | 测试环境配置错误 | 检查测试环境 |
| 依赖问题 | 依赖版本不匹配 | 更新依赖 |
| 异步问题 | 异步操作未正确处理 | 使用 `await` 或 `done` |
| 随机失败 | 测试不稳定 | 检查测试代码 |

### 3.2 测试失败的排查步骤

```
1. 查看测试报告，确认失败的测试
2. 查看失败的具体信息
3. 在本地复现失败
4. 分析失败原因
5. 修复代码或测试
6. 重新执行测试
```
