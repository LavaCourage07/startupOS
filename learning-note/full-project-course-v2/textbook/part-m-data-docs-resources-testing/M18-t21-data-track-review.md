# M18 T21 数据轨道综合复盘——从 `data/` 到数据生命周期管理

小林学完了 M14—M17，对 OriginOS 的数据有了基本了解。但她发现这些知识是分散的——M14 讲目录结构，M15 讲文件格式，M16 讲数据迁移，M17 讲备份恢复。她想知道：**这些数据知识之间是什么关系？从数据创建到数据删除，完整的数据生命周期是怎样的？**

本课把 M14—M17 的分散知识汇集成一条完整的数据生命周期链路，让读者理解数据从创建到删除的完整流程。

## 场景：从"数据创建"到"数据删除"

### 1.1 数据生命周期概览

```mermaid
flowchart LR
    A[数据创建] --> B[数据写入]
    B --> C[数据读取]
    C --> D[数据更新]
    D --> E[数据迁移]
    E --> F[数据备份]
    F --> G[数据归档]
    G --> H[数据删除]
```

| 阶段 | 对应课次 | 核心操作 | 产物 |
| --- | --- | --- | --- |
| 数据创建 | M14 | Agent/项目创建 | `blocks.json` |
| 数据写入 | M15 | 会话记录、实践日志 | `events.jsonl`、`turn-*.json` |
| 数据读取 | M15 | 加载记忆、知识库 | `Memory.md`、`Knowledge.md` |
| 数据更新 | M14—M15 | 更新摘要、索引 | `Memory.md`、`index.md` |
| 数据迁移 | M16 | Web ↔ Desktop 迁移 | 迁移后的数据 |
| 数据备份 | M17 | 备份 `data/` 目录 | 备份文件 |
| 数据归档 | M14 | 归档到 `archival/` | `hnsw-index.bin`、`entries.jsonl` |
| 数据删除 | M14 | 删除 Agent/项目 | 清理后的目录 |

### 1.2 每个阶段的责任边界

**数据创建（M14）**：

- **责任**：初始化 Agent 或项目的数据目录
- **输入**：Agent/项目配置
- **输出**：`blocks.json`、初始目录结构
- **失败后果**：Agent/项目无法正常使用

**数据写入（M15）**：

- **责任**：记录会话、实践日志等数据
- **输入**：会话事件、实践记录
- **输出**：`events.jsonl`、`turn-*.json`
- **失败后果**：历史记录丢失

**数据读取（M15）**：

- **责任**：加载记忆、知识库等数据
- **输入**：`Memory.md`、`Knowledge.md`
- **输出**：Agent 的上下文
- **失败后果**：Agent 无法理解历史上下文

**数据更新（M14—M15）**：

- **责任**：定期更新摘要和索引
- **输入**：历史记录
- **输出**：更新后的 `Memory.md`、`index.md`
- **失败后果**：Agent 的上下文过时

**数据迁移（M16）**：

- **责任**：在 Web 和 Desktop 之间迁移数据
- **输入**：源目录
- **输出**：目标目录
- **失败后果**：数据丢失或不一致

**数据备份（M17）**：

- **责任**：定期备份数据
- **输入**：`data/` 目录
- **输出**：备份文件
- **失败后果**：数据丢失后无法恢复

**数据归档（M14）**：

- **责任**：将旧数据归档到 `archival/`
- **输入**：历史记录
- **输出**：`hnsw-index.bin`、`entries.jsonl`
- **失败后果**：数据占用过多空间

**数据删除（M14）**：

- **责任**：清理 Agent/项目的数据
- **输入**：Agent/项目 ID
- **输出**：清理后的目录
- **失败后果**：数据残留

## 2. 数据生命周期中的关键依赖关系

### 2.1 依赖关系图

```mermaid
flowchart LR
    A[blocks.json] --> B[memory/history/]
    B --> C[Memory.md]
    C --> D[knowledge/]
    D --> E[practice/]
    E --> F[archival/]
    F --> G[数据删除]
```

**关键理解**：数据生命周期是线性的，每个阶段依赖前一个阶段的输出。如果某个阶段失败，后续阶段可能无法正常进行。

### 2.2 数据一致性的保障

| 保障措施 | 作用 | 实现方式 |
| --- | --- | --- |
| 原子写入 | 防止数据写入过程中断 | 先写入临时文件，再重命名 |
| 校验和验证 | 防止数据损坏 | 计算 SHA256 校验和 |
| 版本控制 | 防止版本不兼容 | 在 `blocks.json` 中记录版本 |
| 定期备份 | 防止数据丢失 | 定期备份 `data/` 目录 |

## 3. 数据生命周期中的关键文件

### 3.1 文件的创建时机

| 文件 | 创建时机 | 更新时机 | 删除时机 |
| --- | --- | --- | --- |
| `blocks.json` | Agent/项目创建时 | Agent/项目更新时 | Agent/项目删除时 |
| `Memory.md` | 首次落盘时 | 每 N 轮落盘时 | Agent/项目删除时 |
| `events.jsonl` | 首次会话时 | 每轮会话后 | Agent/项目删除时 |
| `Knowledge.md` | 首次知识更新时 | 周期更新时 | Agent/项目删除时 |
| `hnsw-index.bin` | 首次归档时 | 归档更新时 | Agent/项目删除时 |

### 3.2 文件的生命周期状态

```mermaid
flowchart LR
    A[创建] --> B[活跃]
    B --> C[归档]
    C --> D[删除]
```

| 状态 | 描述 | 示例 |
| --- | --- | --- |
| 创建 | 文件首次生成 | `blocks.json` 创建 |
| 活跃 | 文件被频繁读写 | `events.jsonl` 追加 |
| 归档 | 文件不再活跃，移至归档 | `hnsw-index.bin` |
| 删除 | 文件被清理 | Agent/项目删除 |

## 4. 数据生命周期管理的方法

### 4.1 监控数据健康

| 监控项 | 方法 | 异常信号 |
| --- | --- | --- |
| 数据大小 | 监控 `data/` 目录的大小 | 大小异常增长 |
| 文件数量 | 监控文件数量 | 文件数量异常减少 |
| 写入延迟 | 监控写入操作的延迟 | 延迟异常增加 |
| 读取错误 | 监控读取操作的错误率 | 错误率异常增加 |

### 4.2 数据清理策略

| 策略 | 描述 | 适用场景 |
| --- | --- | --- |
| 定期清理 | 定期删除旧数据 | 数据量持续增长 |
| 按需清理 | 用户手动删除数据 | 用户需要释放空间 |
| 自动归档 | 自动将旧数据归档 | 需要保留历史数据 |

## 6. 练习：数据生命周期管理

### 任务 A：定位数据问题

已知信息：Agent 的 `Memory.md` 文件内容为空。

问题：可能的原因是什么？应该如何排查？

### 任务 B：设计数据清理策略

已知信息：Agent 的数据目录大小持续增长，需要清理旧数据。

问题：应该如何设计清理策略？需要考虑哪些因素？

### 参考答案

**任务 A：**

| 排查步骤 | 操作 |
| --- | --- |
| 1 | 检查 `memory/history/` 是否有历史记录 |
| 2 | 检查 Agent 配置中的落盘阈值 |
| 3 | 检查是否有更新 Memory.md 的逻辑 |
| 4 | 检查日志是否有更新失败的错误 |

可能原因：Agent 尚未达到落盘阈值；更新逻辑失败；历史记录缺失。

**任务 B：**

| 策略 | 说明 |
| --- | --- |
| 定期归档 | 将旧数据归档到 `archival/`，释放活跃空间 |
| 删除旧数据 | 删除超过一定时间的历史记录 |
| 压缩数据 | 压缩 JSONL 文件，减少存储空间 |
| 用户确认 | 删除前征求用户确认 |

## 7. 口头验收

学完本课后，不看正文也应能回答下面五个问题：

1. 数据生命周期包含哪些阶段？每个阶段的责任是什么？
2. 数据生命周期中的关键依赖关系是什么？
3. 如何保障数据一致性？有哪些措施？
4. 数据清理有哪些策略？各有什么优缺点？
5. 当你遇到数据问题时，应该如何排查？

合格回答不要求背诵每个阶段的具体操作，但必须能说清数据生命周期的完整流程、各阶段的依赖关系、以及问题排查方法。能说清"数据从创建到删除的完整流程"比只说清"某个文件的作用"更重要。
