# M17 数据备份和恢复如何阅读——从 `data/` 到安全副本

小林担心她的 Agent 数据会丢失。她想知道 OriginOS 的数据是如何备份的、备份存储在哪里、以及如何在数据丢失后恢复。

本课解决一个理解问题：当你面对 OriginOS 的数据备份和恢复需求时，怎样理解备份策略、执行备份、以及在数据丢失后恢复。

## 场景：从"数据丢失"到"安全恢复"

### 1.1 数据备份的需求来源

OriginOS 的数据备份需求主要来自以下场景：

| 场景 | 描述 | 备份频率 |
| --- | --- | --- |
| 应用升级 | 升级前备份，防止升级失败导致数据丢失 | 每次升级前 |
| 数据迁移 | 迁移前备份，防止迁移过程中数据损坏 | 每次迁移前 |
| 定期备份 | 定期备份，防止意外数据丢失 | 每天/每周 |
| 用户手动备份 | 用户主动备份重要数据 | 随时 |

### 1.2 备份的内容

OriginOS 的备份内容包括：

| 内容 | 路径 | 说明 |
| --- | --- | --- |
| Agent 数据 | `data/agents/` | Agent 的记忆、知识库、实践日志 |
| 项目数据 | `data/projects/` | 项目的协作会话、知识库 |
| 配置文件 | `package.json`、`electron-builder.yml` 等 | 应用配置 |

## 2. 备份策略

### 2.1 全量备份 vs 增量备份

| 策略 | 描述 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 全量备份 | 备份整个 `data/` 目录 | 简单、完整 | 占用空间大、备份时间长 |
| 增量备份 | 只备份新增或修改的文件 | 占用空间小、备份时间短 | 恢复时需要合并多个备份 |

### 2.2 备份步骤

**全量备份的步骤**：

1. **停止应用**：确保应用没有在运行
2. **选择备份目标**：确定备份文件的存储位置
3. **复制数据**：将 `data/` 目录复制到备份位置
4. **验证备份**：检查备份文件的完整性
5. **记录备份信息**：记录备份时间、版本、内容

**示例命令**：

```bash
# 备份 Web 版本数据
tar -czf backup-$(date +%Y%m%d).tar.gz packages/web/data/

# 备份 Desktop 版本数据
tar -czf backup-$(date +%Y%m%d).tar.gz packages/desktop/data/
```

## 3. 恢复策略

### 3.1 恢复步骤

**全量恢复的步骤**：

1. **停止应用**：确保应用没有在运行
2. **备份当前数据**：在恢复前备份当前数据（防止恢复失败）
3. **删除当前数据**：删除 `data/` 目录
4. **恢复备份数据**：将备份数据复制到 `data/` 目录
5. **验证恢复**：启动应用，检查功能正常

**示例命令**：

```bash
# 恢复备份
tar -xzf backup-20260902.tar.gz -C packages/web/
```

### 3.2 恢复风险

| 风险 | 描述 | 应对措施 |
| --- | --- | --- |
| 数据覆盖 | 恢复时覆盖当前数据 | 恢复前备份当前数据 |
| 版本不兼容 | 备份数据的版本与当前应用不兼容 | 检查版本兼容性 |
| 数据损坏 | 备份文件损坏 | 使用校验和验证备份文件 |
