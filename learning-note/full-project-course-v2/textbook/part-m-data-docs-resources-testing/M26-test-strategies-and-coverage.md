# M26 测试策略和覆盖率如何阅读——从"测什么"到"测多少"

小林想知道 OriginOS 的测试策略是什么、测试覆盖率是多少、以及如何判断测试是否充分。

本课解决一个理解问题：当你面对 OriginOS 的测试策略时，怎样理解测试的目标、覆盖率的含义、以及测试的充分性。

## 场景：从"测什么"到"测多少"

### 1.1 测试策略概览

OriginOS 的测试策略遵循"测试金字塔"：

| 测试层级 | 目标 | 覆盖率要求 | 工具 |
| --- | --- | --- | --- |
| 单元测试 | 验证单个函数或组件 | > 80% | Vitest |
| 集成测试 | 验证模块间的交互 | > 70% | Vitest + MSW |
| E2E 测试 | 验证完整的用户场景 | 关键路径 100% | Playwright |

### 1.2 测试覆盖率

测试覆盖率衡量测试对代码的覆盖程度：

| 覆盖率类型 | 含义 | 计算方式 |
| --- | --- | --- |
| 语句覆盖率 | 被测试的语句比例 | 已执行语句 / 总语句 |
| 分支覆盖率 | 被测试的分支比例 | 已执行分支 / 总分支 |
| 函数覆盖率 | 被测试的函数比例 | 已执行函数 / 总函数 |
| 行覆盖率 | 被测试的行比例 | 已执行行 / 总行数 |

## 2. 测试覆盖率的解读

### 2.1 覆盖率的高低

| 覆盖率 | 含义 | 风险 |
| --- | --- | --- |
| 100% | 所有代码都被测试覆盖 | 低——但可能存在无效测试 |
| 80-99% | 大部分代码被覆盖 | 低——少数路径未测试 |
| 50-79% | 一半代码被覆盖 | 中——大量路径未测试 |
| < 50% | 少量代码被覆盖 | 高——大量路径未测试 |

### 2.2 覆盖率的局限性

**高覆盖率 ≠ 高质量测试**：

| 情况 | 说明 |
| --- | --- |
| 无效测试 | 测试了代码，但没有验证结果 |
| 虚假覆盖 | 测试执行了代码，但没有验证边界条件 |
| 遗漏路径 | 测试覆盖了代码，但遗漏了异常路径 |

**关键理解**：覆盖率是必要但不充分的条件。高覆盖率只能说明代码被执行了，不能保证代码是正确的。

## 3. 测试充分性的判断

### 3.1 测试充分性的标准

| 标准 | 说明 | 验证方法 |
| --- | --- | --- |
| 功能覆盖 | 所有功能都有对应的测试 | 检查功能列表和测试用例 |
| 边界覆盖 | 边界条件都被测试 | 检查输入边界值 |
| 异常覆盖 | 异常路径都被测试 | 检查错误处理代码 |
| 集成覆盖 | 模块间的交互都被测试 | 检查集成测试 |

### 3.2 测试充分性的判断方法

```
1. 列出所有功能点
2. 检查每个功能点是否有对应的测试
3. 检查边界条件是否被测试
4. 检查异常路径是否被测试
5. 检查模块间的交互是否被测试
```

## 5. 练习：测试策略分析

### 任务 A：判断测试充分性

已知信息：某模块的语句覆盖率为 90%，但分支覆盖率只有 50%。

问题：测试是否充分？为什么？

### 任务 B：设计测试策略

已知信息：需要测试一个用户注册功能。

问题：应该设计哪些测试用例？

### 参考答案

**任务 A：**

| 分析 | 说明 |
| --- | --- |
| 语句覆盖率 | 90%——较高 |
| 分支覆盖率 | 50%——较低 |
| 结论 | 测试不充分——大量分支未被测试 |
| 风险 | 未测试的分支可能包含 bug |

**任务 B：**

| 测试用例 | 说明 |
| --- | --- |
| 正常注册 | 输入有效的用户名和密码 |
| 用户名已存在 | 输入已存在的用户名 |
| 密码太短 | 输入少于最小长度的密码 |
| 密码格式错误 | 输入不符合要求的密码 |
| 空输入 | 不输入任何内容 |
| SQL 注入 | 输入包含 SQL 注入的内容 |

## 6. 口头验收

学完本课后，不看正文也应能回答下面五个问题：

1. 测试策略的目标是什么？各层级的覆盖率要求是多少？
2. 覆盖率有哪些类型？各有什么含义？
3. 高覆盖率是否等于高质量测试？为什么？
4. 如何判断测试是否充分？
5. 当你需要评估测试质量时，应该看什么指标？

合格回答不要求背诵每个覆盖率的具体数值，但必须能说清测试策略、覆盖率的含义、以及测试充分性的判断。能说清"测试是否充分"比只说清"覆盖率是多少"更重要。
