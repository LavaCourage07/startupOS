# G27：数据存储类型系统——`types.ts` 定义了哪些类型

> 本课核心问题：`types.ts` 定义了哪些核心类型？InstanceData、ConceptSchema、QueryParams 是怎么设计的？

## 1. 开篇场景：小王的咖啡馆数据需要结构化存储

小王的本体已经生成：
- Domain："餐饮零售，社区咖啡馆"
- Concept："商品"、"供应商"、"订单"

现在小王要录入具体的商品数据：
- 商品 A：名称"埃塞俄比亚耶加雪菲咖啡豆"，类别"咖啡豆"，单价 128，库存 50
- 商品 B：名称"哥伦比亚慧兰咖啡豆"，类别"咖啡豆"，单价 98，库存 30

这些数据需要被结构化存储。`types.ts` 就是定义这些结构的。

## 2. 两种类型设计策略

### 2.1 松散类型

```ts
interface Instance {
  id: string;
  data: any;  // 任意数据
}
```

优点：灵活，可以存任何数据。
缺点：没有类型安全，容易出错。

### 2.2 严格类型

```ts
interface InstanceData {
  id: string;
  conceptId: string;
  domainId: string;
  ontologyId: string;
  fields: Record<string, unknown>;
  meta: InstanceMeta;
}
```

OriginOS 选择了**严格类型**。

## 4. 类型之间的关系

```
InstanceData
  ├── id, conceptId, domainId, ontologyId
  ├── fields: Record<string, unknown>
  └── meta: InstanceMeta
        ├── createdAt, updatedAt
        ├── createdBy
        └── version

ConceptSchema
  ├── conceptId, domainId, ontologyId, name
  └── fields: ConceptField[]
        ├── name, type, required
        ├── defaultValue, description
        ├── enum, autoGenerated
        └── relatedConceptId, relationType, cardinality

InstanceRelation
  ├── id, type
  ├── sourceInstanceId, targetInstanceId
  └── sourceConceptId, targetConceptId
```

## 5. 设计亮点

### 5.1 分离业务数据和元数据

```ts
interface InstanceData {
  fields: Record<string, unknown>;  // 业务数据（动态）
  meta: InstanceMeta;              // 元数据（固定结构）
}
```

业务数据和元数据分离，便于：
- 独立验证（Schema 只验证 `fields`）。
- 独立更新（修改业务数据不影响元数据）。
- 独立查询（可以按元数据排序/过滤）。

### 5.2 版本号内嵌

```ts
interface InstanceMeta {
  version: number;  // 每次更新自动递增
}
```

版本号内嵌在元数据中，不需要额外的版本表。

### 5.3 灵活的字段类型

```ts
type FieldType = 'string' | 'number' | 'boolean' | 'date' | 'array' | 'object' | 'relation';
```

支持 7 种字段类型，覆盖大部分业务场景。

## 7. 小实验：验证类型

### 步骤一：创建 InstanceData

```ts
import { InstanceData } from '@originos/core/lib/features/ontology-data-store';

const instance: InstanceData = {
  id: 'inst-001',
  conceptId: 'product',
  domainId: 'retail',
  ontologyId: 'ont-001',
  fields: {
    name: '埃塞俄比亚耶加雪菲咖啡豆',
    category: '咖啡豆',
    price: 128,
    stock: 50,
  },
  meta: {
    createdAt: Date.now(),
    updatedAt: Date.now(),
    createdBy: 'user',
    version: 1,
  },
};

console.log(instance.fields.name);  // "埃塞俄比亚耶加雪菲咖啡豆"
console.log(instance.meta.version); // 1
```

### 实验结论

类型系统清晰，分离了业务数据和元数据，便于后续扩展。

## 9. 章节收束

本课的核心认知是 **`types.ts` 定义了严格的数据类型，分离了业务数据和元数据，支持 7 种字段类型和完整的查询参数**。

我们看到的几个关键设计：

- **严格类型**：`InstanceData`、`ConceptSchema`、`InstanceRelation` 等都有明确的类型定义。
- **数据分离**：`fields`（业务数据）和 `meta`（元数据）分离。
- **版本内嵌**：`meta.version` 自动递增。
- **灵活字段**：支持 7 种字段类型。
- **查询参数**：支持过滤、排序、分页。
