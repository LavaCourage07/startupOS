# D15：认知共享类型

## 课程助手主线中的位置

认知数据会在 turn 结束、记忆写入和周期整理之间传递。共享类型使这些模块交换结构化事实而不是互相 import 实现，避免认知模块与 Pi Agent runtime 形成双向依赖。

## 本章推理图

```mermaid
flowchart LR
    Project[课程助手项目] --> Contract[类型与路径合同]
    Contract --> Core[Core 基础设施]
    Core --> Evidence[文件或可观察结果]
```

图从左至右表示同一项目的数据不直接跳到磁盘：先经过合同，Core 才能在不同运行环境中得到一致结果。本章要找出的不是“某个函数存在”，而是这条箭头为什么不能被绕过。

## 源码阅读方法

先打开本章正文中给出的真实入口，定位类型或函数的输入和返回值；再向上查调用方，向下查它依赖的路径、存储或实现。阅读时记录三个事实：谁拥有业务语义，谁只负责基础设施，失败后由谁决定用户可见结果。

## 常见误解

把接口、类型、路径或出口当成“没有业务价值的胶水代码”会导致阅读断裂。它们正是 Web、Core、Desktop 与测试可以使用同一项目对象而不互相复制实现的原因。

## 练习与验收

1. 找到本章机制在课程助手保存或恢复链路中的上游调用者。
2. 说明它的输入、输出和失败责任分别属于哪一层。
3. 写出绕过该边界会造成的一种具体后果。

能用真实源码路径解释这三项，即通过本章；下一章继续解决同一项目主线中的下一个边界。
