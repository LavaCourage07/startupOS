# OriginOS 全项目教材写作标准

## 1. 教材定位

这是一套面向有基本前端知识的大学生的正式源码教材。读者可以理解 HTML、CSS、JavaScript、TypeScript、React 与基本接口请求，但不预设其理解 Agent、LLM、Prompt、工具调用、文件存储、Next.js 服务端、Electron、IPC、状态机、认知系统、OpenSpec 或测试体系。

教材目标不是让读者“看过文件”，而是使读者能够独立阅读、解释、修改、测试并继续扩展 OriginOS 当前版本。

## 2. 不可替代的原则

1. 正式课件是教材，不是源码阅读清单、操作指南、课程大纲或交付说明。
2. 文件地图只用于证明覆盖范围，不能替代正文教学。
3. 每节课必须有实际、充实、连续的讲解；不能以模板化短文、通用图、通用练习或空白占位文件凑课数。
4. 每个 Part 的每节课使用独立文件，目录和课号清晰稳定，例如 `A01-...md`、`D01-...md`。
5. 不得把“文件已经创建”或“课程已编号”称为“教材已经完成”。只有正文、图解、源码、测试、练习和验收达到本标准后，才算完成。

## 3. 全书主线

课程不能是彼此孤立的主题集合。每个 Part 必须选择一条可观察的真实主线，并让同一对象、同一数据或同一用户动作跨章节推进。

示例：Core 基础设施以“用户创建项目，项目被保存，关闭应用后重新恢复”为主线。每一章只解决这条链路中的一个新问题，再留下自然通向下一章的问题。

```text
用户动作
-> 用户界面入口
-> 真实调用链
-> 数据和类型合同
-> 存储或运行时状态
-> 错误边界
-> 测试证据
-> 练习和验收
```

## 4. 每节课的正式结构

每节课应按问题需要组织，不机械堆标题；但必须完整覆盖以下内容：

1. **开篇场景**：从用户可观察现象、真实需求或故障开始。
2. **核心问题**：明确本章只解决的一个主问题和必要子问题。
3. **直觉与概念阶梯**：先用通俗语言建立直觉，再给准确术语、边界和相近概念的区别。
4. **图解**：图前说明图要回答什么；图后逐节点、逐箭头、逐数据解释，并标明对应源码。
5. **源码精读**：从真实入口出发，只截取当前论点需要的代码窗口；解释输入、输出、状态、分支、调用者、被调用者和设计原因。
6. **真实调用链**：说明控制权和数据如何从上游到下游流动，以及本章在哪个边界停止。
7. **关键类型与数据示例**：解释实际字段、约束和 JSON/请求/响应/状态变化，而不是只说“类型是合同”。
8. **失败路径与边界**：说明配置缺失、数据损坏、权限失败、重复调用、跨层依赖或环境差异时会怎样。
9. **测试证据**：提供真实测试入口；解释 Given/When/Then、测试证明什么以及尚未证明什么。若缺少测试，必须明确写出缺口。
10. **练习和验收**：至少包含定位、调用链追踪、解释、微改动、验证中的合适项目；给出明确完成标准。
11. **章节收束**：总结新建立的心智模型，指出仍未解决的问题，并自然引向下一章。

## 5. 源码与链接标准

1. 所有源码引用必须来自真实项目文件，使用可点击的相对 Markdown 链接和必要的 `#L` 行号。
2. 每个链接前后保留空格，避免影响点击和阅读。
3. 不能只链接文件第一行就声称完成源码讲解；必须定位关键代码窗口并逐段分析。
4. 不得编造调用链、类型、测试或运行行为。无法确认的内容必须继续阅读源码或明确标注为待验证。
5. 源码说明必须区分：当前事实、设计推断、历史遗留限制和未来改进建议。

## 6. 图解与小黑图标准

1. Mermaid 用于真实架构、时序、状态、控制流和数据流；一张图只解释一个问题。
2. Mermaid 必须使用可渲染的合法语法，不能出现未经验证的复杂标签或错误节点写法。
3. 图前给出阅读问题；图后解释每个角色、节点、箭头、数据和停止边界。
4. 小黑图不是每节必需。它用于难以从代码直观看见的抽象变化、角色关系、认知转折或常见误解。
5. 使用小黑图时，小黑必须承担解释任务；正文必须说明图中隐喻对应的系统机制，不能把图当装饰。

## 7. 可读性与文风

1. 使用正式教材语言，不出现提示词、协作过程、交付过程、“为了满足要求”、自我辩解或面向作者的工作备注。
2. 由浅入深：先现象，后概念；先局部，后全局；先可观察行为，后抽象原理。
3. 采用清晰标题、短段落、表格、代码窗口、停顿思考和章节小结组织内容。
4. 不靠堆砌术语、重复结论或泛泛类比增加篇幅。每段文字都必须推动理解、定位源码或解释设计决策。
5. 需要重复的核心概念应在后续章节被回收和应用，而不是只在第一次出现时定义。

## 8. 质量验收

一节课只有同时满足以下问题时才可标记完成：

| 检查项 | 验收问题 |
| --- | --- |
| 连续性 | 本章是否接住上一章问题，并引出下一章？ |
| 真实性 | 所有路径、行号、调用链、类型和测试是否可在仓库复查？ |
| 深度 | 是否解释了为什么、失败时怎样、替代方案或边界在哪里？ |
| 可读性 | 不懂该领域的前端读者能否按文字和图逐步跟上？ |
| 图解 | 图是否承担具体推理任务，并得到逐项解释？ |
| 源码 | 是否真的带读关键代码，而非只放链接？ |
| 验证 | 是否给出可执行或可观察的练习与验收？ |

任何一项不满足，课程只能标记为草稿，不能标记为完成。
