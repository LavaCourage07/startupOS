# A6. 从维护者视角读项目

> 类型：源码课大纲
> 状态：待审阅，确认后扩写为完整版课件。

## 本节定位

- 问题：为什么项目同时有源码、Story、OpenSpec、QA 和变更记录？
- 覆盖：`docs/DOCUMENTATION-MANAGEMENT.md`、`docs/index.md`、`docs/changes/`
- 图解：需求 -> 设计 -> 实现 -> 测试 -> 归档闭环
- 验收：能解释“写代码前先看 Story / OpenSpec”的原因。

## B. Monorepo 与工程系统

## 完整版课件要求

- 使用固定结构：问题 -> 图解 -> 源码入口 -> 调用链 -> 关键类型 -> 测试入口 -> 练习 -> 验收。
- 至少包含 1 张 Mermaid 图。
- 如本节涉及核心概念、复杂心智模型或阶段总结，需要加入 Xiaohei 配图。
- 源码入口必须写真实路径，不能只写模块名。
- 调用链必须能从入口追到下一层实现或明确说明边界。
- 测试入口必须写真实测试路径；没有测试时要说明缺口。
